_Snapshot from 2024. Some tools and numbers have changed._

The Dwarves Operations team keeps one checklist per recurring job. This page gathers them so a person on duty can find the right list without browsing a folder. The lists fall into three groups: people, clients and money, and projects.

| Checklist                   | Use it when                                                |
| --------------------------- | ---------------------------------------------------------- |
| Hiring                      | Running a recruiting round, from job post to offer         |
| Candidate evaluation        | Judging whether a candidate fits                           |
| Onboarding                  | A new employee joins the team                              |
| Leave requests and holidays | An employee asks for leave, or a public holiday approaches |
| Offboarding                 | An employee leaves the team                                |
| Social insurance paperwork  | An employee asks for social insurance and a contract       |
| Company assets              | Anyone borrows or returns a company asset                  |
| Consulting contract         | Reviewing a client contract before signing                 |
| Billing and invoices        | Issuing, sending and chasing a client invoice              |
| Vietnam invoice             | Producing a Vietnamese tax invoice                         |
| Project initialization      | Starting a new project, from paperwork to setup            |
| Project communication       | Setting the communication rules of a project               |
| Back up artifacts           | Every 3 months, to record the project's progress           |
| Project handover            | A new member takes over project work                       |
| Project case study          | Writing the case study of a finished project               |
| Project archive             | Closing a finished project                                 |

**This series has 2 parts.** Each one reads on its own.

1. The people lifecycle (this page)
2. [Clients, money and projects](operations-checklists-clients-projects.md)

## People

### Hiring

The checklist presents how hiring proceeds.

**Resume collecting**

- [ ] Job Description
- [ ] List of job sites/hiring channels
- [ ] Job post materials
- [ ] Hiring system (Notion)

**Timeline**

- [ ] Invitation & calendar send out (also the interviewer assigned?)
- [ ] Interview result after each round must be reported
- [ ] Responsive?
- [ ] Follow the process? Skip any round?
- [ ] Ignore or miss any applicant?
- [ ] Meet deadline for each round?
- [ ] Does the assignment grader carefully grade the applicant assignment?
- [ ] Conflict of interest? (Applied for the referral model)

**Dates to fix**

- [ ] Deadline for application
- [ ] Time of interview
- [ ] Time of confirmation emails
- [ ] Time of on-boarding
- [ ] Time of probation

**Offering**

- [ ] If a candidate is the right fit, move quickly
- [ ] Before you make an offer, make sure you know exactly what the offer package will look like and don't be vague about it
- [ ] If the candidate turns you down, remain friendly and maintain a relationship. They might change their minds in the future.
- [ ] Enough information? (salary, probation, title, benefit, start date...)
- [ ] Are the department head, accounting, operation aware of the offer?

**Material**

- [ ] Handbook
- [ ] Pre-assignment Test
- [ ] Assignment
- [ ] Templates for multiple scenarios (see [Dwarves email templates](/email-template-library))

### Candidate evaluation

The checklist shows how to evaluate a candidate.

**Background and skills**

- [ ] Logic qualified
- [ ] English skills qualified
- [ ] Technical (specialized) knowledge and skills qualified

**Personalities.** The [hiring approach](hiring-approach.md) shows how we read these. A short list works as a shortcut:

- [ ] Doer
- [ ] Curiosity
- [ ] Problem-solving
- [ ] Learner
- [ ] Teamwork
- [ ] Open-minded
- [ ] Collaborative
- [ ] Supportive
- [ ] Any issues in previous works?
- [ ] Personality check via social?

### Onboarding

Through onboarding, the employee gradually forms their own perspective and their fit with Dwarves. This is the stage when they decide whether or not to commit to the company.

![Onboarding flow](checklists/assets/onboarding-checklist_onboard.webp)

**Important notes.** The original list names six onboarding pitfalls:

- [ ] Starting on-boarding on the new hire's first day
- [ ] Not setting expectations and company policies.
- [ ] Instituting a one-size-fits-all approach for every new hire.
- [ ] Involving only the new hire's direct team or department.
- [ ] Limiting on-boarding to one week.
- [ ] Forgetting to follow-up.

**Offer email.** An offer email should cover these points:

- [ ] Net/gross salary
- [ ] Onboarding day

**Onboarding email.** After sending the offer email and getting the confirmation from the candidate, send the onboarding email. It asks the new hire to complete the onboarding process, which includes:

- [ ] Request setting up Transferwise and its account number
- [ ] Request Identity card information
- [ ] [Insurance information](https://www.notion.so/IT-Security-Measures-Document-3eb7f8ee49b841038523304164291184?pvs=21)
- [ ] Fill the Fortress form
- [ ] Sign the contract with LLC
- [ ] Create onboarding schedule
- [ ] Invite to Dwarves Foundation Discord server

**Onboarding call with the Operations team.** The Operations team makes sure the new hire knows their position, prepares their personal account for company access, and understands the daily workflow. The new hire must also know how the company runs, benefits and perks, essential paperwork, the review period, and the expectations for culture fit. The call introduces:

- [ ] The goal of the probation
  - Team, Leader, and Project Introduction
  - Personal 60 days plan
- [ ] Workspace Introduction
  - Discord: Team's communication channel
  - Basecamp: Task, document, and onleave request management
- [ ] Onboarding to Reward system (ICY)
  - Create and connect crypto wallet to Dwarves Foundation server
  - Create and connect GitHub account to Dwarves Foundation server
- [ ] The team's workflow
  - Daily report and check-in
  - On-leave request and reimbursement
  - Communication channels

**Add the new member to the working space and communication channels**

- [ ] Self-introduction in Discord. The introduction should include:
  - How we should address you (name/nickname/English name)
  - Your role at Dwarves
  - Which project you will join
  - What your goals are as a software engineer
  - Ops: mention the teammates on Discord for a warm welcome
- [ ] Onboard the new hire to the project (the original list named four teammates here: Thanh, Giang, Ngoc and Huy)

**Meeting with the team lead: probation guideline (60-day plan)**

- [ ] Goals and targets for the 2-month probation period
- [ ] Schedule the review date after 2 months
- [ ] Introduce the new hire to the department head
- [ ] Make sure the new hire has a line manager/leader
- [ ] Understand the work scope and expectations
- [ ] Check in on work experience and culture fit, with bi-weekly check-ins
  - First 2 weeks: culture fit and workflow
  - First probation: SOW and expectations
  - Second probation: the next 6 months
- [ ] Engage and share Dwarves activities. Share with the team about:
  - Technical topics
  - News
  - Practices and examples
  - Assign topics for Radio Talk
  - Apply and train for mentor/coach

### Leave requests and holidays

As an Ops Team or Manager member, you manage leave requests so projects run smoothly and everyone knows who is away. This checklist guides you through verifying, approving or denying leave requests, and handling holiday notifications.

**Verification and notification**

- [ ] Acknowledge the employee's leave request.
- [ ] Discuss the request with the employee.
- [ ] Confirm the leave details.
- [ ] Align workload and resources to prevent interruptions.
- [ ] Reassign critical tasks (if necessary).
- [ ] Plan for covering the employee's responsibilities (if necessary).

**Approval or denial.** After you receive the Basecamp ticket notification:

If approved:

- [ ] Mark the ticket as done and note the employee's return date.
- [ ] Ensure Basecamp sends a notification to involved parties and updates Google Calendar.
- [ ] Inform the client via email.
- [ ] Update the project timeline (if necessary).
- [ ] Monitor project progress during the employee's leave.

If denied:

- [ ] Note the reason in the ticket.
- [ ] Inform the employee and provide feedback (if applicable).
- [ ] Suggest alternative solutions or adjustments (if possible).

**1-2 weeks before a holiday**

- [ ] Send an official announcement via email to all clients (see the holiday templates in [Dwarves email templates](/email-template-library)).
- [ ] Confirm that all ongoing projects have a holiday plan in place.
- [ ] Announce the holiday schedule on Discord to all team members.

**2-3 days before a holiday**

- [ ] Remind clients informally via Slack or other communication channels.
- [ ] Review the holiday plan with the team to address any last-minute issues or concerns.
- [ ] Send a short reminder about the holiday schedule on Discord.

### Offboarding

An offboarding process must ensure three things:

1. Your employee feels good.
2. The departure causes minimal disruption.
3. The termination process is well wrapped, so company policy and procedures are all followed.

**Project offboarding**

- [ ] Last day confirmation with client by email
- [ ] Resource replacement
- [ ] Project handoff completed
- [ ] Source code backup

**Company offboarding: exit interviews and final communications**

- [ ] Exit interview with lead/manager
  - [ ] Gather feedback
  - [ ] Invite to join alumni activities on Discord/events
- [ ] Exit talk with HR/Ops
  - [ ] Remind about important points in the Contractor Agreement
- [ ] Last day and final paycheck informed
- [ ] Offboarding email: remind on survival terms in the Contractor Agreement
- [ ] Thank you and farewell letter to personal email
- [ ] Farewell message posted (optional)
- [ ] Update the DF resource planning file
- [ ] Update LinkedIn and endorse Dwarves

**Company offboarding: account and access management**

- [ ] Remove email account
- [ ] Remove Git account
- [ ] Remove 1Password account
- [ ] Remove Basecamp account
- [ ] Remove access to other work channels
- [ ] Remove database access
- [ ] Update Fortress profile
- [ ] Update Discord role to Alumni and remove Discord access from work-related channels

**Company offboarding: equipment and resources**

- [ ] Office card / work device (laptop, phone) if applicable
- [ ] Any other company-owned equipment
- [ ] Remind the member to delete source code from their machine

**After the departure**

- [ ] Follow up on any outstanding items or handover tasks
- [ ] Conduct a brief team meeting to address any gaps left by the departure
- [ ] Update relevant documentation and contact lists

**Handover transfer**

- [ ] Conduct handover transfer sessions with team members
- [ ] Document any unique scripts or tools created by the employee
- [ ] Capture information about ongoing experiments or research

This checklist aims for a smooth, positive offboarding that keeps good relations with the departing employee while protecting company interests. Adapt it to the specific role and the company's technology and processes.

### Company assets

This checklist is for administrators and employees to manage company assets.

**For the admin**

Lending:

- [ ] Collect the request on Basecamp at Woodland > To dos > Asset Request
- [ ] Check the status of the asset
- [ ] Have the borrower's information logged in Airtable
- [ ] Set a deadline for returning the asset

Collecting:

- [ ] Collect the asset from the borrower
- [ ] Check the status of the asset
- [ ] Report for damage caused (if any)
- [ ] Tick done on the To-dos ticket

**For the employee**

Borrowing:

- [ ] Request on Basecamp at Woodland > To dos > Asset Request
- [ ] Collect the asset from the Admin/Ops Associate
- [ ] Report for damage (if any)
- [ ] Set up a deadline for returning

Returning:

- [ ] Check the asset status
- [ ] Report for damage (if any)
- [ ] Sync up with the Admin/Ops Associate
