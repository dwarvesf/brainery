## The finding

In Build Club, bievh shared that they had upgraded the graphics on a game prototype, then clarified the work was not AI-generated. They said they sat down to tune each pixel and play through each beat by hand, which turns the update from a visual refresh into a craft decision.

## Why it matters to us

Small prototypes often get judged by the first few seconds of feel: whether the sprite reads, whether the motion lands, whether the beat makes the player continue. Generated assets can help a team move faster, but this thread is a reminder that polish is not only about producing visuals. For game-like interfaces, the useful work may be in the slow loop: draw, play, notice friction, redraw, replay. That loop is harder to outsource because the judgment comes from the interaction, not just from the asset.

## Take it further

- Capture before-and-after clips for the next graphics pass, so the team can see which pixels or beats changed the feel.
- Write down the hand-polish checklist: readability, timing, feedback, contrast, rhythm, and where the first playtest breaks.
- Compare one hand-tuned asset against one generated asset in the same scene, then note what each path saved or cost.
- If the prototype is public, link the build so the note can move from a craft observation into a playable field report.
